# FizMat HQ — штаб репетитора

Одностраничное приложение (PWA) для репетитора: расписание, ученики, платежи, финансы,
задачи. Работает офлайн, данные хранятся локально и синхронизируются с вашим Google
Диском. Весь код — в одном файле `index.html`.

## Быстрый запуск (GitHub Pages)

1. Создайте репозиторий и залейте файлы из этой папки (файл `index.html` и иконки
   должны лежать в корне репозитория).
2. Settings → Pages → Source: `Deploy from a branch`, ветка `main`, папка `/root`.
3. Откройте выданный адрес `https://<user>.github.io/<repo>/`. Нужен HTTPS — Pages его
   даёт автоматически; без него не заработают офлайн-режим и вход через Google.

Всё приложение статическое — подойдёт любой хостинг (Netlify, Vercel, свой сервер).

## Google Календарь — если ничего не появляется

Это почти всегда одна и та же причина: для вашего Google-проекта (тот же, что уже
используется для входа/Диска) **не включён Calendar API** — это отдельный переключатель,
он не включается сам по себе, даже если Диск давно работает.

Как включить (2 минуты):

1. Откройте [Google Cloud Console](https://console.cloud.google.com/apis/library/calendar-json.googleapis.com)
   (ссылка сразу открывает нужную страницу — «Google Calendar API»).
2. Убедитесь вверху страницы, что выбран **тот же проект**, что и для входа в приложение
   (обычно единственный/основной проект вашего аккаунта).
3. Нажмите **Enable** (Включить). Готово — ничего больше настраивать не нужно.
4. Вернитесь в приложение, откройте Настройки → Google Календарь и попробуйте снова
   («Отправить неделю» / «Загрузить события»). Может понадобиться заново подтвердить
   доступ — это нормально.

Приложение теперь показывает точную причину ошибки от Google во всплывающем окне (а не
просто «ошибка») — если после включения API всё ещё не работает, это окно подскажет,
в чём дело: например, если браузер блокирует всплывающие окна для входа, или если вы
вошли под другим Google-аккаунтом, у которого нет доступа к нужному календарю.

Обмен работает в двух режимах.

**Автоматический двусторонний (бета).** Настройки → Google Календарь → включите
«Автоматическая синхронизация». Уроки приложения появляются в календаре, а правки и
удаления переносятся в обе стороны сами: при открытии, каждые 3 минуты, при возврате на
вкладку и через ~12 секунд после вашей правки. Конфликты решаются по времени: побеждает
более поздняя правка. Окно — 14 дней назад и 60 вперёд.

Предохранители, потому что синхронизация умеет удалять:
- проведённые уроки не удаляются при удалении в Google (они связаны с оплатой) — такой
  урок просто отвязывается от календаря;
- если в Google за раз удалено больше 25 событий, синхронизация останавливается и
  ничего не удаляет;
- удаления, пришедшие из календаря, можно откатить кнопкой «Отменить» (8 секунд);
- уроки из шаблонов расписания, удалённые в Google, не создаются заново.

**Включайте синхронизацию после резервной копии** (Настройки → Экспорт JSON) — это
первая версия, и хотя логика покрыта автотестами, на живом аккаунте её стоит проверить
осторожно. Если что-то пойдёт не так — выключите переключатель и нажмите «Сбросить
состояние».

**Ручной (без удалений).** Кнопки «Только неделю» / «Только загрузить» — обмен только
добавлением, ничего нигде не удаляется. Подходит, если не хочется давать синхронизации
право удалять.

Чего синхронизация не делает: не переносит серии повторяющихся событий Google как серии,
не синхронизирует участников, напоминания, цвета и вложения, работает только с основным
календарём, и не переносит ученика/цену/оплату — это остаётся в приложении.

## Настройка Google с нуля (Диск + Календарь)

Нужна, только если начинаете заново или переносите приложение на новый Google-проект —
если вход через Google уже работает, этот раздел можно пропустить (кроме шага про
Calendar API выше).

В [Google Cloud Console](https://console.cloud.google.com/):

1. **APIs & Services → Library** — включите **Google Drive API** и **Google Calendar API**.
2. **OAuth consent screen** — заполните, в разделе Scopes добавьте:
   - `https://www.googleapis.com/auth/drive.appdata` — синхронизация данных;
   - `https://www.googleapis.com/auth/calendar.events` — обмен с календарём.
3. **Credentials → Create credentials → OAuth client ID → Web application.**
   В **Authorized JavaScript origins** добавьте адрес сайта
   (`https://<user>.github.io` и `http://localhost:5173` для локальной разработки).
4. Скопируйте `Client ID` и подставьте в `index.html` вместо значения `GDRIVE_CLIENT_ID`
   (в самом верху скрипта). В сборке — то же значение в `build-vite/src/main.jsx`.

## Данные и резервные копии

- Данные лежат в `localStorage` и дублируются в `IndexedDB` того же домена, а при входе
  через Google — ещё и в скрытой папке приложения на вашем Диске.
- Настройки → Резервная копия → «Экспорт JSON» делает полную копию; «Импорт JSON»
  восстанавливает.
- Удаления можно отменить в течение 8 секунд (кнопка «Отменить» внизу экрана).

## Сборка без Babel (опционально, быстрее)

Сейчас `index.html` компилирует JSX в браузере через `babel-standalone` (~3 МБ).
В папке `build-vite/` — тот же код, собираемый заранее (быстрее старт, можно включить
строгий CSP без `unsafe-eval`). Запуск:

```bash
cd build-vite
npm install
npm run build     # статика в dist/
```

Подробности и оговорки — в `build-vite/README.md`. Полный список изменений — в
`CHANGES.md`.
